Permalist Project

Problem Being Solved

The Permalist-Project solves the problem of managing a to-do list that persists across sessions. Instead of losing tasks when the page is refreshed or the app restarts, the application stores tasks in a database, allowing users to reliably add, edit, and delete items while keeping their data permanently saved.

Key Design Decisions

The project uses Node.js and Express to handle server-side logic and routing, with EJS for server-side rendering of dynamic pages. A PostgreSQL database is used to store tasks, ensuring persistence and real-world backend integration. The architecture follows a straightforward CRUD pattern, prioritizing simplicity, readability, and learning full-stack fundamentals over complex abstractions.

What I Would Improve Next

Future improvements would include adding user authentication so multiple users can manage separate task lists, improving the UI with a modern frontend framework like React, and exposing a fully RESTful API for better scalability. Adding automated tests, validation, and deployment pipelines would also make the application more production-ready and maintainable.

Blog-API-Project

Problem Being Solved

The Blog-API-Project solves the problem of managing blog content through a backend API that supports creating, reading, updating, and deleting blog posts. It demonstrates how a blog system can function through structured API endpoints while allowing content to be displayed dynamically to users.

Key Design Decisions

The project is built with Node.js and Express to handle API routing and request handling, using EJS for server-side rendering of blog pages. It follows RESTful API principles with clear endpoints and uses in-memory storage to keep the project simple and focused on API logic and full-stack learning. The separation between the API logic and the rendered views helps reinforce clean architecture and modular development.

What I Would Improve Next

Future improvements would include adding a persistent database such as PostgreSQL or MongoDB so data is not lost on server restart, implementing user authentication and authorization for managing posts securely, and improving input validation and error handling. Converting the frontend into a modern SPA (React or Vue) that consumes the API would also make the project more scalable and production-ready.
